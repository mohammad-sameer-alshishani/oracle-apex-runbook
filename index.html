1Prerequisites

  1. Windows 10/11 x64, 8 GB+ RAM, about 15 GB free disk.
  2. Java 17 or newer (ORDS needs it). Check:
    CMD
    java -version
    If it's missing or older than 17, install JDK 21 from adoptium.net and tick Set JAVA_HOME and Add to PATH. Open a new CMD afterwards.
  3. Downloads (an Oracle account may be required):
    • Database: Oracle AI Database 26ai Free → Windows zip
    • APEX: APEX downloads → apex_26.2.zip (apex_26.2_en.zip installs faster)
    • ORDS: ORDS downloads → ords-latest.zip
    • Toad for Oracle: Quest official site (free trial; needs a valid license after that)
    • Free alternative to Toad: Oracle SQL Developer
Passwords: don't use @ in any Oracle password. In a command like user/pass@host, everything after the first @ is read as the host, which causes ORA-12262. Use # or _ instead.

2Check for an existing Oracle install

If the 26ai installer says it's already installed, another Oracle database (often 21c XE) is on the PC.

2.1List Oracle services

CMD
sc query state= all | findstr /i "Oracle"
  • OracleServiceXE means 21c XE (PDB name XEPDB1).
  • OracleServiceFREE means 23ai/26ai Free (PDB name FREEPDB1).

2.2Option A: keep XE

Skip step 3. Set PDB on the left to XEPDB1. APEX 24.2 is the safer choice on 21c.

2.3Option B: remove XE (export any data you need first)

  1. Settings → Apps → Oracle Database 21c Express Edition → Uninstall.
  2. Remove leftover services and registry keys:
    CMD
    net stop OracleServiceXE
sc delete OracleServiceXE
sc delete OracleJobSchedulerXE
sc delete OracleOraDB21Home2TNSListener
sc delete OracleOraDB21Home2MTSRecoveryService
sc delete OracleVssWriterXE
reg delete HKLM\SOFTWARE\Oracle /f
    Service names can differ. Delete whatever 2.1 listed.
  3. Delete the old install folder (usually C:\app\<user>\product\21c) and remove its bin entry from PATH.
  4. Reboot.

4Connect and fix connection problems

4.1Connect locally (works even if the listener is down)

CMD
sqlplus / as sysdba
SQL>
SELECT name, open_mode FROM v$pdbs;

If isn't READ WRITE, open it and make it open on every startup. Run each line on its own, with no comment after the ; (a trailing comment caused ORA-03405):

SQL>
ALTER PLUGGABLE DATABASE {{PDB}} OPEN;
ALTER PLUGGABLE DATABASE {{PDB}} SAVE STATE;
ALTER SYSTEM REGISTER;

4.2Change passwords to ones without @

SQL>
ALTER USER sys IDENTIFIED BY {{SYS_PWD}} CONTAINER=ALL;
ALTER USER system IDENTIFIED BY {{SYSTEM_PWD}} CONTAINER=ALL;
exit

4.3Check the listener

CMD
lsnrctl status
  • "no listener": run lsnrctl start, then ALTER SYSTEM REGISTER; as SYS.
  • Services list shows freepdb1 but HOST=: the listener ignores localhost (error ORA-12543). Fix with 4.4.

4.4Make the listener accept localhost

  1. Open Notepad as administrator and open:
    path
    {{ORACLE_HOME}}\network\admin\listener.ora
  2. Change the TCP line's host to 0.0.0.0:
    listener.ora
    LISTENER =
  (DESCRIPTION_LIST =
    (DESCRIPTION =
      (ADDRESS = (PROTOCOL = TCP)(HOST = 0.0.0.0)(PORT = {{PORT}}))
      (ADDRESS = (PROTOCOL = IPC)(KEY = EXTPROC1521))
    )
  )
  3. Restart the listener and re-register:
    CMD
    lsnrctl stop
lsnrctl start
sqlplus / as sysdba
    SQL>
    ALTER SYSTEM REGISTER;
exit

Quick workaround without editing the file: use or 127.0.0.1 as the host.

4.5Test a network connection to the PDB

CMD
sqlplus sys/{{SYS_PWD}}@{{HOST}}:{{PORT}}/{{PDB}} as sysdba

If a password still contains @, leave it out and type it at the prompt: sqlplus sys@ as sysdba.

9Create a schema manually

In Oracle, a schema is a user. Run this as SYS or SYSTEM in the PDB.

CMD
sqlplus / as sysdba
SQL>
ALTER SESSION SET CONTAINER = {{PDB}};

CREATE USER {{SCHEMA}} IDENTIFIED BY {{SCHEMA_PWD}}
  DEFAULT TABLESPACE USERS
  TEMPORARY TABLESPACE TEMP
  QUOTA UNLIMITED ON USERS;

GRANT CREATE SESSION, CREATE TABLE, CREATE VIEW, CREATE SEQUENCE,
      CREATE PROCEDURE, CREATE TRIGGER, CREATE TYPE, CREATE SYNONYM,
      CREATE MATERIALIZED VIEW, CREATE JOB TO {{SCHEMA}};

Reset a forgotten password or unlock the account:

SQL>
ALTER USER {{SCHEMA}} IDENTIFIED BY {{SCHEMA_PWD}} ACCOUNT UNLOCK;

Find a schema whose name you don't remember (APEX may have named it differently):

SQL>
SELECT username, account_status, created FROM dba_users ORDER BY created DESC FETCH FIRST 10 ROWS ONLY;

11One-time setup for dumps

11.1Create the Windows folder

CMD
mkdir {{DUMP_PATH}}

11.2Create the directory object and grant access

CMD
sqlplus / as sysdba
SQL>
ALTER SESSION SET CONTAINER = {{PDB}};
CREATE OR REPLACE DIRECTORY {{DUMP_DIR}} AS '{{DUMP_PATH}}';
GRANT READ, WRITE ON DIRECTORY {{DUMP_DIR}} TO {{SCHEMA}};
GRANT DATAPUMP_EXP_FULL_DATABASE, DATAPUMP_IMP_FULL_DATABASE TO {{SCHEMA}};
SELECT directory_name, directory_path FROM dba_directories WHERE directory_name = UPPER('{{DUMP_DIR}}');
exit

The two DATAPUMP_* roles are only needed to import into a different schema (remap) or to export other schemas. Exporting and importing your own schema works without them.

11.3If Oracle can't write to the folder

Errors ORA-39087, ORA-39070 or ORA-29283 mean the Oracle service account can't write there:

CMD
icacls {{DUMP_PATH}} /grant "Everyone":(OI)(CI)F

For a tighter grant, use the account shown in services.msc → OracleServiceFREE → Log On instead of Everyone.

12Export (create the dump)

Run expdp and impdp at the C:\> prompt, not at SQL> (that gives SP2-0734). Inside SQL*Plus, put HOST in front of the command. Each command is one line, so don't add ^ line breaks when pasting.

12.1Whole schema (most common)

CMD
expdp {{SCHEMA}}/{{SCHEMA_PWD}}@{{HOST}}:{{PORT}}/{{PDB}} schemas={{SCHEMA}} directory={{DUMP_DIR}} dumpfile={{DUMP_FILE}} logfile={{LOG_PREFIX}}_exp.log

Success ends with Job ""."SYS_EXPORT_SCHEMA_01" successfully completed. Files: \ and the log.

12.2Selected tables only

CMD
expdp {{SCHEMA}}/{{SCHEMA_PWD}}@{{HOST}}:{{PORT}}/{{PDB}} tables={{TABLES}} directory={{DUMP_DIR}} dumpfile={{LOG_PREFIX}}_tables.dmp logfile={{LOG_PREFIX}}_tables_exp.log

12.3Structure only, no data

CMD
expdp {{SCHEMA}}/{{SCHEMA_PWD}}@{{HOST}}:{{PORT}}/{{PDB}} schemas={{SCHEMA}} content=METADATA_ONLY directory={{DUMP_DIR}} dumpfile={{LOG_PREFIX}}_ddl.dmp logfile={{LOG_PREFIX}}_ddl_exp.log

12.4For an older target database (e.g. 19c)

CMD
expdp {{SCHEMA}}/{{SCHEMA_PWD}}@{{HOST}}:{{PORT}}/{{PDB}} schemas={{SCHEMA}} version=19 directory={{DUMP_DIR}} dumpfile={{LOG_PREFIX}}_v19.dmp logfile={{LOG_PREFIX}}_v19_exp.log

12.5Whole PDB (as SYSTEM)

CMD
expdp system/{{SYSTEM_PWD}}@{{HOST}}:{{PORT}}/{{PDB}} full=y directory={{DUMP_DIR}} dumpfile=full.dmp logfile=full_exp.log

13Import (restore the dump)

GoalUse
Make a copy in a different schema, original untouched13.1
Restore tables and data into the same schema13.2
Replace everything in the same schema (tables, procedures, packages, views…)13.3
Replace only code objects, keep current tables13.4

13.1Into another schema (remap)

Needs DATAPUMP_IMP_FULL_DATABASE on (11.2). is created automatically.

CMD
impdp {{SCHEMA}}/{{SCHEMA_PWD}}@{{HOST}}:{{PORT}}/{{PDB}} directory={{DUMP_DIR}} dumpfile={{DUMP_FILE}} remap_schema={{SCHEMA}}:{{TARGET_SCHEMA}} table_exists_action=REPLACE logfile={{LOG_PREFIX}}_imp_remap.log

Then give the new schema a password so you can log in:

SQL>
ALTER SESSION SET CONTAINER = {{PDB}};
ALTER USER {{TARGET_SCHEMA}} IDENTIFIED BY {{TARGET_PWD}} ACCOUNT UNLOCK;

13.2Same schema: tables and data

CMD
impdp {{SCHEMA}}/{{SCHEMA_PWD}}@{{HOST}}:{{PORT}}/{{PDB}} directory={{DUMP_DIR}} dumpfile={{DUMP_FILE}} table_exists_action=REPLACE logfile={{LOG_PREFIX}}_imp.log
table_exists_actionEffect on a table that already exists
SKIP (default)Leaves it as is
APPENDKeeps rows and adds the dump's rows
TRUNCATEEmpties it, loads the dump's rows, keeps the current structure
REPLACEDrops it and recreates it with the structure and data from the dump
Existing procedures, packages, views, sequences and triggers are not replaced. They're skipped with ORA-31684: Object type … already exists. Use 13.3 or 13.4 to replace them.

13.3Same schema: replace everything

Drop the schema, then import as SYSTEM. The import recreates the user, its grants and all objects exactly as they were in the dump.

CMD
sqlplus / as sysdba
SQL>
ALTER SESSION SET CONTAINER = {{PDB}};
DROP USER {{SCHEMA}} CASCADE;
exit
CMD
impdp system/{{SYSTEM_PWD}}@{{HOST}}:{{PORT}}/{{PDB}} directory={{DUMP_DIR}} dumpfile={{DUMP_FILE}} logfile={{LOG_PREFIX}}_imp_full.log
You can't run this import as , because that user no longer exists after the drop. Make sure the SYSTEM password works first (4.2).

13.4Same schema: replace code only

This writes the DDL to a script instead of importing:

CMD
impdp {{SCHEMA}}/{{SCHEMA_PWD}}@{{HOST}}:{{PORT}}/{{PDB}} directory={{DUMP_DIR}} dumpfile={{DUMP_FILE}} sqlfile={{LOG_PREFIX}}_code.sql include=PROCEDURE,FUNCTION,PACKAGE,VIEW,TRIGGER

Open \_code.sql in Toad, change CREATE to CREATE OR REPLACE, and run it as .

14Verify the import

  1. The import should end with successfully completed. completed with N error(s) is often just grant warnings. Check the .log in .
  2. Compare objects and row counts (as SYS or SYSTEM):
    SQL>
    SELECT owner, object_type, COUNT(*) AS cnt
FROM dba_objects
WHERE owner IN ('{{SCHEMA}}', '{{TARGET_SCHEMA}}')
GROUP BY owner, object_type
ORDER BY object_type, owner;

SELECT COUNT(*) FROM {{SCHEMA}}.YOUR_TABLE;
SELECT COUNT(*) FROM {{TARGET_SCHEMA}}.YOUR_TABLE;
  3. Remove a test copy:
    SQL>
    DROP USER {{TARGET_SCHEMA}} CASCADE;

15Export the APEX application

A schema dump does not include your APEX app. App definitions are stored in the APEX engine schema, so export them separately.

  1. From the UI: App Builder → your app → Export / Import → Export. This saves a .sql file.
  2. With SQLcl (scriptable):
    CMD
    sql {{SCHEMA}}/{{SCHEMA_PWD}}@{{HOST}}:{{PORT}}/{{PDB}}
    SQL>
    apex export -applicationid {{APP_ID}}
apex export -applicationid {{APP_ID}} -split
    -split writes one file per component, which works well with Git.
  3. Restore order: create the workspace and schema → import the dump (13) → App Builder → Import the app .sql.
